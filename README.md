## 📖 Описание проекта

Проект представляет собой программную оболочку экспертной системы для подбора комнатных растений в зависимости от условий помещения (освещение, полив, сложность ухода, безопасность).

В основе работы приложения лежит **алгоритм обратного логического вывода (Backward Chaining)**. В отличие от прямого вывода, система начинает рассуждение с заданной гипотезы (цели) и рекурсивно проверяет, подтверждается ли она фактами рабочей памяти или цепочками подцелей через правила базы знаний.

---

## ✨ Особенности системы

* **Обратный логический вывод:** Проверка достижимости конкретной цели через доказательство её условий-предпосылок.
* **Защита от циклов и переполнения:** Встроенный контроль посещенных целей (`path`) и ограничение предельной глубины поиска (`max_depth = 100`).
* **Разделение базы знаний и движка:** Правила хранятся во внешнем файле `rules.txt` и загружаются динамически.
* **Редактирование правил "на лету":** Встроенный GUI позволяет просматривать, модифицировать и сохранять правила в файл напрямую из интерфейса.
* **Протоколирование шагов вывода:** Формирование подробного журнала рассуждений с отступами, наглядно отражающими глубину проверки гипотез.
* **Отсутствие сторонних зависимостей:** Проект написан на стандартной библиотеке **Python** с использованием фреймворка **Tkinter**.

## 🖥️ Руководство пользователя

1. **Редактирование базы правил:** В верхнем текстовом поле отображаются текущие правила. Кнопка **«Загрузить правила»** считывает файл `rules.txt`, кнопка **«Сохранить правила»** записывает изменения обратно в файл.
2. **Задание рабочей памяти:** В поле *«Начальное состояние рабочей памяти»* введите известные исходные факты (по одному факту на строку).
3. **Установка цели:** В поле *«Целевая ситуация»* введите проверяемую гипотезу вида `объект = значение`.
4. **Запуск вывода:** Нажмите кнопку **«Проверить достижимость цели»**.
5. **Анализ результата:** В нижнем поле отобразится статус (`ЦЕЛЬ ДОКАЗАНА` / `ЦЕЛЬ НЕ ДОКАЗАНА`) и пошаговый протокол рассуждений.

## 📝 Формат правил и базы знаний

### Правила (`rules.txt`)
Записываются продукциями вида:
```text
ЗАКЛЮЧЕНИЕ => УСЛОВИЕ_1 И УСЛОВИЕ_2 И ...
```
* Слева от `=>` указывается доказываемый факт (заключение).
* Справа через связку ` И ` перечисляются факты-предпосылки.
* Символ `#` в начале строки обозначает комментарий.

Пример:
```text
# Группа неприхотливых растений
категория = неприхотливые => освещение = тень И уход = простой
растение = Сансевиерия => категория = неприхотливые И полив = редкий
```

### Факты
Записываются построчно в формате:
```text
объект = значение
```
При сравнении фактов регистр букв и пробелы по краям игнорируются (`тень` эквивалентно `Тень`).

## 🧪 Примеры сценариев для проверки

### Сценарий 1: Успешное доказательство цели
* **Правило:** `растение = Сансевиерия => освещение = тень И уход = простой`
* **Факты в памяти:**
  ```text
  освещение = тень
  уход = простой
  ```
* **Целевая ситуация:** `растение = Сансевиерия`
* **Результат:** `ЦЕЛЬ ДОКАЗАНА: растение = Сансевиерия`

### Сценарий 2: Нехватка исходных данных
* **Правило:** `растение = Фикус => освещение = яркое И полив = умеренный`
* **Факты в памяти:**
  ```text
  освещение = яркое
  ```
* **Целевая ситуация:** `растение = Фикус`
* **Результат:** `ЦЕЛЬ НЕ ДОКАЗАНА: растение = Фикус` (в протоколе: `Условие не доказано: полив = умеренный`).

## 🏗️ Архитектура и алгоритм работы

Приложение состоит из двух ключевых компонентов:

1. **`MainWindow` (Графический интерфейс):** Отвечает за взаимодействие с пользователем, чтение/запись `rules.txt` и передачу данных в логический процессор.
2. **`ExpertSystem` (Ядро логического вывода):**
   * **`Fact` и `Rule`:** Классы данных для представления атомарных фактов и продукционных правил.
   * **`prove(goal, depth, path)`:** Рекурсивная процедура обратного вывода:
     1. Проверяет наличие `goal` среди известных фактов рабочей памяти.
     2. Проверяет наличие `goal` в стеке `path` для предотвращения бесконечных циклов.
     3. Находит все правила, где заключение совпадает с `goal`.
     4. Последовательно доказывает каждую посылку найденных правил через рекурсивный вызов `prove`.
     5. Фиксирует каждый шаг в списке `log` с добавлением отступов глубины стека.
